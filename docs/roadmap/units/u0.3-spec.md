## Goal

Set up the real Cucumber code base so every later unit starts the same way:
one layout, one command to run every check, automatic checks on GitHub for
every pull request, a real PostgreSQL in tests, and the release-notes tooling.
After U0.3, U0.2a can write its tests (G2) and show them failing in CI.

## User stories

| # | As a… | I want… | So that… |
|---|---|---|---|
| S1 | Owner | broken code to be caught before it reaches `main` | the live app is never updated with failing tests |
| S2 | Owner | the code organised by feature (plants, batches, events…) | I can find and read the part I care about |

## Acceptance criteria

**Checks that must fail CI** (each proven by a deliberately broken commit at G2)

- **AC1** *Given* a pull request with a lint error, *when* CI runs, *then* the run fails and names the file and line.
- **AC2** *Given* a type error, *when* CI runs, *then* it fails.
- **AC3** *Given* a failing test, *when* CI runs, *then* it fails.
- **AC4** *Given* coverage of the app code below 80 %, *when* CI runs, *then* it fails and shows the coverage.
- **AC5** *Given* a pull request title that isn't `type: description` (feat, fix, perf, refactor, docs, test, chore, ci), *when* CI runs, *then* it fails, because release notes are built from these titles.
- **AC6** *Given* CI has failed, *then* the pull request isn't merged: the **merge rule** applies (merges are done only by the Owner together with Claude, who checks that every CI check is green first), and the PR template's "CI is green" box must be ticked ([Q1](#open-questions-for-the-owner)). GitHub can't enforce this on the free plan.
- **AC6a** *Given* the repository settings, *then* only **squash merging** is allowed and the squash commit takes the pull request's title ([Q2](#open-questions-for-the-owner)).

**Local and test set-up**

- **AC7** *Given* a fresh clone on a Mac with Docker and uv, *when* the README's set-up steps are followed, *then* all checks run with **one command** in under 10 minutes.
- **AC8** *Given* the test database, *then* it is PostgreSQL 17 (not SQLite), and the init script has created both roles `cucumber_owner` and `cucumber_app` ([U0.2 design §4](u0.2-design.md#4-database-level-protection)).
- **AC9** *Given* a test marked to run as the app user, *when* it starts, *then* `SELECT current_user` returns `cucumber_app` (U0.2 re-check N4).
- **AC10** *Given* the E2E smoke test, *when* it runs in CI, *then* a browser at **375 px** width opens the login page (Playwright).

**Layout and settings**

- **AC11** *Given* the repo, *then* the Django project lives in one folder with one app per feature (`plants`, `batches`, `events`, `references`, `accounts`, `core`), each with its own `tests/` folder.
- **AC12** *Given* settings loaded with **no** `DJANGO_DEBUG` variable, *then* DEBUG is **off** (debug must be switched on explicitly, never by default), and *given* DEBUG off and no `DJANGO_SECRET_KEY` or `DJANGO_ALLOWED_HOSTS`, *then* the app refuses to start with a clear message (U0.1 G4 review H2: the spike defaulted to DEBUG on).
- **AC13** *Given* the repo, *then* no secret is committed; `.env` is ignored and `.env.example` lists every variable without values.

**Release tooling** ([release process](../release-process.md))

- **AC14** *Given* merged pull requests since the last tag, *when* the *Draft release* workflow runs, *then* a **draft** GitHub Release is created with the next `YYYY.MM.N` version, a git-cliff technical section, and the PRs' Staff notes.
- **AC15** *Given* the repo, *then* Dependabot proposes weekly updates for Python packages (uv) and GitHub Actions.
