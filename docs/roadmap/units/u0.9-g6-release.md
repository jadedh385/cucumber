## Findings

1. **The Draft release workflow ran twice** and made two identical drafts
   (`2026.10.6`, `2026.10.7`). The Owner deleted `2026.10.7` and its tag. Run the workflow
   once, and check `gh run list --workflow "Draft release"` before running it again.
2. **A `git log` over `ssh -tt` opens a pager** and waits for RETURN, which looks like a
   hang. Set `GIT_PAGER=cat` in rehearsal scripts, or pipe the script over stdin
   (`ssh host 'bash -l -s' < script.sh`) with no tty.
3. **The home-network addresses of both machines timed out on port 22 again;** the
   `-remote` aliases worked. The first remote attempt hung until the Owner signed in
   to Cloudflare Access in a browser. When it reconnects it prints a login URL with a
   token; it was not copied into this note.
4. **`current` is not rewritten by a restore,** so the forward deploy printed "(was 2026.10.6)".
   Cosmetic.
5. **The PR body had gone stale** (it still said "G2 in progress") and had no `## Staff note`.
   It was rewritten before the merge, since it becomes the squash commit.
6. Application code was not changed at G6.
