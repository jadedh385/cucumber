## Production image build (design §3.3, risk M8)

The script [`uat/u0_10a_image_check.sh`](../../../uat/u0_10a_image_check.sh) does
the whole step in one command from the Owner's Mac (the shop network, or the
`-remote` name):

```bash
uat/u0_10a_image_check.sh cucumber-server            # or cucumber-server-remote
```

It sends the branch's files with `git archive` over ssh (no clone, no fetch, no
change to `~/cucumber`), then on the production Mac: prints the machine and
Docker's architecture and the free disk; runs `docker build` of the whole image;
builds the `build` stage again from the cache and looks inside it (`uname -m`,
`ls -l /opt/tools`, `sha256sum /opt/tools/*`); checks the run image holds no CLI
and does hold `cucumber.css`; and **deletes both tags and the files** whatever
happens (`trap`). It never runs `docker compose`, `stop` or `restart`, and
leaves the build cache to docker (the deploy command clears what is a week old).
Base images it has to pull (`python:3.13-slim`, `uv`) stay: the deploy uses the
same ones.

The build itself is the check: `scripts.css fetch` deletes and refuses a download
whose SHA-256 differs from the pinned `linux-arm64` hash (`55fd0b24…98195`), and
the next layer runs the CLI to build the stylesheet, so a wrong or unrunnable
binary fails the build. The sha256sum line shows it by eye.

**Rehearsal on this Mac** (Apple silicon, Docker Desktop, `linux/arm64`: the same
architecture the production Mac's Docker builds for): **done, and it passed.** The script's remote half was run
here against `git archive` of the branch (`af5f399`, the same code as `2b96d10`):
`uname -m` `arm64`, Docker `linux/arm64`; the `RUN python -m scripts.css fetch`
layer ran for 7.0 s (a real download: the cache was empty); inside the build stage
`uname -m` says `aarch64` and `/opt/tools/tailwindcss-4.3.3-linux-arm64` is
109,881,488 bytes with SHA-256
`55fd0b241214eff3de1e8ee4f22796662f2d2e7a49bcfca7477cfd0bac398195`, **the pinned
`linux-arm64` hash**; the CLI ran (`cucumber.css`, 72,248 bytes, the same size as the
`linux-x64` build on staging); the run image has no `/opt/tools`. Exit 0; both tags
and the files were deleted. This proves the arm64 binary, the hash and the script;
it does **not** prove the production Mac's own Docker, network or disk. That is
still the Owner's run (Q-G5-b).

Phase 1 re-checks when its first big read exists. **The limit is not a problem at
this volume.**

**Not measured here:** a phone on mobile data and Cloudflare's tunnel add far more
than any figure above; this is the app's own time.
