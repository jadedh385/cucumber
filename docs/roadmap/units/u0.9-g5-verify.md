- **The inactive check on a save** costs about **1.1–1.3 ms** (round 1: 6.9 →
  8.0 ms; round 2: 9.3 → 10.6 ms), measured as the same save made with
  `picked=False` and with the default, one after the other. It makes **3
  queries** on the save that picks the most (one each for the medium, the stage
  and the location), the design's "at most three key look-ups" (Q3). A save
  that picks nothing makes none.
- The lists are a few rows each, so reading them does not depend on the data
  volume; the 0.3–0.4 ms is a round trip.
- Nothing U0.9 touches is slower in a way a phone user could notice.

debug log was full); the second ran straight after the load and its "before"
side was disturbed (typical save 27.6 ms). `scripts.timing_10x`'s measure uses
up units in the batches it picks, so it cannot run twice on the same data: each
run started from a restore of the loaded dump.
