## 10× timing on the production Mac

`uat/timing_10x.sh` (new in step 6, kept in the repo): a throwaway database
with 3,000 plants, 10,001 batches and 362,000 entries, 7,000 waiting for
review; production running beside it, on battery; 30 runs each.

| Action | Median | p95 |
|---|--:|--:|
| Save an entry, typical batch | 4.2 ms | 4.4 ms |
| Save an entry, busy batch (2,000 entries) | 23 ms | 29 ms |
| Open a batch, split, void, correction | 4–24 ms | 5–27 ms |
| Mark one queue item reviewed | 8 ms | 10 ms |
| Review queue, 7,000 waiting | 1.48 s | 1.51 s |
| `check_projections`, every batch (nightly) | 31.8 s | — |

Every save is far under the half-second a phone user notices. The review
queue is the one slow spot, as in U0.2b (paging already logged to U1.8). The
nightly check takes about three times as long as on the development Mac, still
fine for a job that runs once a night.

## Findings

1. **The production Mac sleeps on battery.** Its battery setting is `sleep 1`,
   so with the charger out it slept after a minute and both tunnels dropped
   (Cloudflare error 1033, 2026-10-18 morning). On the charger `sleep 0` holds.
   Logged in the MacBook runbook; the uptime alert now catches it.
2. **`/` shows Cucumber's *Not Found*.** There is no home page yet, so a person
   who types only the address lands on an error after the email check. Follow-up
   for a later unit: send `/` to the login page.
3. **One Cloudflare login covers every app the policy allows.** The Owner's
   phone, signed in for staging on 2026-10-17, went straight into production.
   Expected Access behaviour (sessions last 30 days); the AC19 code step was
   proved in a private tab. Removing a leaver needs *Revoke session* (Access
   runbook, "Someone leaves").
4. **SSH through the tunnel times out now and then** (banner exchange) on both
   machines; a retry or the home network gets through. The website was never
   affected. Long jobs over SSH run detached (`nohup` + log): a dropped
   connection stopped the first 10× run.
5. **Production deploys are the Owner's to run.** Claude's auto-mode safety
   check stops it deploying to production; the HSTS redeploy was run by the
   Owner from a command Claude gave. Fine as a rule: release.md already makes
   the Owner press Publish.
6. Smaller ones, each fixed and logged in its runbook: DNS over UDP is
   intercepted on the dev network (use TCP); zsh's `read -p` doesn't prompt on
   the production Mac (bash scripts instead); Docker over SSH needed the
   keychain fix (`credsStore` out, placeholder `credHelpers`); `~` in an
   unquoted SSH command is read by this Mac's shell.
