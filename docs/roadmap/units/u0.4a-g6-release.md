G6 for U0.4a is **the first production release**: the first time a version tag
goes onto the production MacBook (`cucumber-server`) with the deploy command
this unit built.

## What G6 asks, and how it applies

| Exit criterion ([gates.md](../gates.md#g6--release)) | For U0.4a | Evidence |
|---|---|---|
| Verified backup taken immediately before release | The deploy command takes the copy (AC10). "Verified" = `pg_restore --list` reads it, as in the G5 restore steps. On a first deploy the database is empty, so the copy proves the step, not the data | Deploy log + `pg_restore --list` output |
| Migration run on production; rollback rehearsed on staging | Deploy the release tag to staging, then roll staging back to what it ran before (AC27, done once in G5; repeated for this tag). Then deploy the tag to production | Staging and production deploy logs |
| Feature switched on (flag) and smoke-tested in production | U0.4a ships no feature behind a flag. Smoke test: deploy's `/health/` check, the login page through `localhost:8000` with **no** Practice banner (AC9), `flag production list` as `cucumber_app` (AC13) | Release log |
| SOP / user guide updated for any changed procedure | No staff procedure changes. The Owner's procedure is new: release steps and restore steps go in a short production runbook (step 8) | Docs diff |
| Staff told what changed | Published GitHub Release. Its staff note is "None" (staff see nothing yet), so the Discord hook posts nothing by design (`announce_release.py`) | Published release link + hook run |

## What stands in the way

1. **Dependency rule.** A unit enters G6 only when every dependency has passed
   G6 ([gates.md](../gates.md#rules), rule 1). U0.4a depends on **U0.3**, which is
   still at G5: AC7 (timed fresh set-up on the MacBook) is open. See Q1.
2. **No production copy yet.** Staging is on the Asus; the MacBook has no
   `~/cucumber/production/` folders, secrets file, deploy key or tools clone.
   U0.4b step 6 plans this together with the tunnels (AC17–AC24). See Q2.
3. **This Mac can't reach the MacBook over SSH.** SSH is on there, admins only
   (`sawat`), but there's no key or `Host cucumber-server` entry here.
4. **Discord webhook not set.** No `DISCORD_RELEASE_WEBHOOK` secret on GitHub.
   With a "None" staff note it isn't needed for this release, but the hook can't
   be proved until it exists. See Q4.
5. **MacBook disk: 25 GB free** (setup log). Production needs roughly 3–5 GB
   (image, database, copies), so it fits now; freeing space is already due
   before R1 (U0.4b).
